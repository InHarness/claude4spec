## What I found

katalog-operacji-m21 row `get_brief_version` (2.1.13) declares a single error code, `BRIEF_NOT_FOUND`, while the mcp-tool entity `brief-tools-get-brief-version` (logic) says a version number outside the history is refused with "a validation error carrying the range of available versions" — a code the row does not declare. The code answered `VERSION_NOT_FOUND` (undeclared anywhere). Assumed: a version off the brief's history (not a positive integer, or past the last one) is `INVALID_ARGUMENT` with the hint `available versions: 1..N` — the artifact family's shared taxonomy (M36 9p8nltkf: an out-of-range window is INVALID_ARGUMENT stating the size) and the same choice made for the plan rows (dev-0002); the code declares `[BRIEF_NOT_FOUND, INVALID_ARGUMENT]` for the row, on MCP and REST alike. Suggest adding `INVALID_ARGUMENT` to the row's error codes (or naming the code in the entity).
