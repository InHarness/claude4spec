## What I found

M28 43k2laa1 at 2.1.55 still says "GitService eksponuje w kodzie także branchContainingCommit i diffRefToWorkingTree" (with a todo to document them). branchContainingCommit existed only to resolve the branch carrying a release's marker for the old HEAD-based push entry (pushOnPush, M25); with pushOnRelease(commit) pushing commit.branch it has no caller and was removed (unused code is removed). The sentence should name only diffRefToWorkingTree. Separately, pre-existing and not touched by this window: the git-service-contract snippet lists a public mergeBase(a, b), while the code has only a private mergeBaseAt(root, a, b) used by sync/listShadows/resolveShadow — either the snippet drops mergeBase or a later brief exposes it. Also: push(branch?) gained an optional second parameter { setUpstreamFrom?: string } (the base branch of a branch created in this run, for `git push -u <remote> <branch>`), which the snippet's push(branch?: string) does not show.

## Suggestion

In M28 43k2laa1 name only `diffRefToWorkingTree` (drop `branchContainingCommit`, removed in 2.1.55 together with pushOnPush). In the `git-service-contract` snippet: show `push(branch?: string, opts?: { setUpstreamFrom?: string })`, and either drop the public `mergeBase(a, b)` (the code has only a private `mergeBaseAt(root, a, b)`) or schedule a brief that exposes it.
