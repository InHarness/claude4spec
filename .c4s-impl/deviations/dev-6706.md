## What I found

M43 `rp99fpc1` embeds `<tagged_list type="spec-operation" tags="decyzja-czlowieka"/>`, L3 `g8adono9` says a record meeting the criterion carries the tag `decyzja-czlowieka`, M55 `nosqcr6z` names the eight v3 operations, and the criteria `ac-rekord-mark-plan-applied-nosi-tag-dec` / `ac-rekord-release-create-nosi-tag-decyzj` require the tag on `mark-plan-applied` and `release-create`. But at 2.1.67 none of the eight spec-operation records (accept-shadow, delete-thread, mark-brief-implemented, mark-patch-applied, mark-plan-applied, release-create, release-restore, release-update) carries the tag: the window's change read returns them as `op: update` with identical `before` and `after`, each with its single module tag only (`m17`, `m05`, `m21`, `m23`, `m10`). So the tagged list in `rp99fpc1` renders empty at the release. The code builds the tag as the page and the criteria say: the catalog rows of those eight operations carry `tags: ['decyzja-czlowieka']` (`src/server/operations/human-decision.ts`, attached in `registerRow`).

## Suggestion

Dodać tag `decyzja-czlowieka` do ośmiu rekordów spec-operation (accept-shadow, delete-thread, mark-brief-implemented, mark-patch-applied, mark-plan-applied, release-create, release-restore, release-update), tak jak mówią M43 `rp99fpc1`, L3 `g8adono9` i kryteria. (ASSUMPTION:dev-6706)
