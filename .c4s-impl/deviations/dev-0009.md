## What I found

M11 L14 (`m11dcmds`) says an unknown `--root-id` on a page command — at 2.1.8 also a system root id such as `plans` — ends with `INVALID_ARGUMENT` carrying the list of `kind: pages` roots in `message`. Since the page commands became server-delegating (0.2.13) they go through `/api/pages/:rootId/...`, whose router refuses an id it cannot resolve before the core is reached: HTTP 404 `ROOT_NOT_FOUND`, message `root '<id>' not found`, the page roots in `hint` (src/server/routes/pages.ts). The router resolves only `kind: pages` runtimes, so `plans` and an unknown id get the identical refusal and the list never names a system root — the 2.1.8 change holds — but the code and the field carrying the list predate the window and differ from the text. MCP and in-process callers get the core's `INVALID_ARGUMENT`.

## Suggestion

Either document `ROOT_NOT_FOUND` (list in `hint`) as the REST/CLI rendering of the core's unknown-root refusal in M11 L14 and the REST error catalog, or schedule a change that makes the page router answer the core's `INVALID_ARGUMENT` with the list in `message`.
