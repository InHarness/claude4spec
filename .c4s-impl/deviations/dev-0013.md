## What I found

M28 `commitForRelease` at 2.1.8 says the commit message is `Release {name}` + blank line + `{description}`, and that an unmet gate returns `{ status: 'skipped' }`. Both sentences are unchanged in this window, and the code has long done otherwise. `GitService.commit` (src/server/services/git.ts) writes `{name}\n\n{description}` with no `Release ` prefix, and just `{name}` when the description is empty. `GitService.commitOnRelease` returns `null` when the gate is off, no repo is detected, or HEAD is detached in `current` mode. `POST /api/releases` then sends `gitSync: null`, and the client reads `null` as "git sync did not run". The build keeps both, since changing them would alter the history format and the response shape that exist outside this window.

## Suggestion

Either make the spec match the code (message `{name}\n\n{description}`; `gitSync: null` when skipped), or confirm the `Release ` prefix and the `skipped` status as intended, and they will be built in a later window.
