## What I found

Section `gpn0fopo` of `pages/modules/m01-project.md` (Start w kontenerze › Pytania otwarte) leaves open whether the image's entrypoint forwards extra container arguments (`$@`) to the server. Section `uxlvmu4n` also says the entrypoint retries the project registration "until it succeeds", but it does not say what happens when the server answers and refuses the directory (a `400` from `POST /api/workspace/projects`, e.g. a path that is not usable). No retry changes that answer.

## What the build assumes (non-blocking)

- Extra container arguments are **not** forwarded. The variable contract (`mcdkzcb6`) is the only input of the start.
- The registration is retried on a refused connection and on a `5xx`. A `4xx` is a final refusal of the directory: the entrypoint logs it, stops the server and the container exits with code 1. It does not retry forever without a message.
