## What I found

M10 (2.1.13) keeps PLAN_NOT_FOUND only for an unknown `path` given on an external channel, and says what get_plan answers in a thread with no plan pinned (`plan: null`). It does not say what `mark_plan_applied` and `get_plan_version` answer on the internal channel when the thread has no plan pinned, nor which code `get_plan_version` gives for a version that is not on the plan's axis. Their rows declare only `PLAN_NOT_FOUND` and `INVALID_ARGUMENT` (the code had NOT_FOUND and VERSION_NOT_FOUND, neither in the row). Assumed: both cases are INVALID_ARGUMENT with a repair hint (nothing pinned → 'write the plan first with update_plan'; version off the axis → the valid range 1..currentVersion). `list_plan_versions` with nothing pinned answers `{ versions: [], total: 0 }`, the same 'empty, not an error' as get_plan's `plan: null`.

## Suggestion
