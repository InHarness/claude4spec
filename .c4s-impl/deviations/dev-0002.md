## What I found

The mcp-tool entity `page-tools-update-page` names the literal mode's field `content` (the complete page, frontmatter included) and describes the tool as writing an EXISTING page. The code on every channel (catalog row `update_page` in src/server/operations/core-operations.ts, MCP tool in src/server/mcp/page-tools.ts, REST `PUT /api/pages/:rootId/*`, CLI) calls it `body` with a separate optional `frontmatter` object, and the literal mode is create-or-replace. This predates the 2.1.7→2.1.8 window (the entity's `before` already said `content`); the window only removed the `sectionIndexed=false` sentence from `logic`. Renaming a public parameter on four channels is a contract change, so the build keeps `body`/`frontmatter` and its shape test asserts that set.

## Suggestion

align the entity's params with the code (`body` + `frontmatter`, create-or-replace in the literal mode), or schedule the rename as its own change.
