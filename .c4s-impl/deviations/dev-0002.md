## What I found

M17 L2 w6cocvik (2.1.55) says the release channel ("kanał wydania") calls gitService.pushOnRelease(gitSync) after commitOnRelease and answers the result in gitPush; the commit paragraph of the same section defines the channel as both the REST route and the MCP tool. The mcp-tool record release-tools-release-create at 2.1.55, however, still returns only gitSync (its `returns`/`sampleReturn` carry no gitPush) and its `logic` ends at "rozgłoszenie i commit git" — no push. The dto `release` (REST) carries gitPush. The implementer built the push on the REST channel only (POST /api/releases answers gitPush) and left release_create as its record states: commit, no push, no gitPush field. ASSUMPTION:dev-0002. If agent-created releases should push too, the release_create record needs gitPush in returns/sampleReturn and a push step in logic.

## Suggestion

Decide whether releases created by the agent (MCP `release_create`) also push. If yes: add `gitPush` to the `release-tools-release-create` record's `returns`/`sampleReturn` and a push step after the commit in its `logic`. If no: say explicitly in M17 L2 w6cocvik that the push runs only on the REST channel (POST /api/releases).
