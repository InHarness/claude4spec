## What I found

M28 section `u5vl07ch`: the `Sync` action of the `git-sync-recover` window calls `POST /api/git/sync` and "its result is handled by the toasts of the Okna field (`8i5qf0xx`)". The toast table has no row for sync `busy` (busy is "a hint at the entry", and the window has no entry), nor for `skipped` / `no-upstream`; it also does not say whether the window closes after Sync.

Implemented under `ASSUMPTION:dev-0002` (unit u4-push-non-fast-forward-recovery, criterion `ac-okno-git-sync-recover-dla-recovery-ki`): the window closes after any Sync result except `busy`; `busy` shows the header's busy hint ("A background task is running — try again in a moment") inside the window, which stays open so Sync can be retried; `skipped` / `no-upstream` close the window with no toast (as dev-0001 for the header).
