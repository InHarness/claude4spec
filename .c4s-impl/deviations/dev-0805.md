## What I found

M12 `ikg2bklu` (Odczyt możliwości) says that in a project without `briefs` the `mcp` channel has two profiles (`chat`, `ask`) and a `brief`/`patch` connection is refused at set-up. M12 also says both mount points carry the same protocol and catalog and differ only in the default of `project`. It does not say how the gate applies to the workspace-bound mount `/api/workspace/mcp`, where one session addresses projects of different types per call. Assumed: the workspace-bound mount refuses `brief`/`patch` at set-up only when no project of the workspace has `briefs`, and otherwise accepts, advertising the catalog of the compat-default project if it holds the profile, else of the first project in workspace order that does. A call that targets a project without `briefs` answers NOT_FOUND, the same as any tool that project's catalog lacks. The spec should say how the profile gate applies on the workspace-bound mount.

Slugs: m12-brief-profile-refused-without-briefs
