## What I found

The `trust-plugins` record (`logic` step 3, flag `--port`) selects a REGISTRY workspace by `defaultPort` when `--cwd` is not a project of a workspace with a home, but the registry also matches workspaces with a home by their `defaultPort`. When `--port` (or its default 4500) is the port of a workspace with a home that `--cwd` does not lie in, `registerProject` there would write the committed `workspace.json`, which M31 `m31cli01` forbids, and creating a second workspace with the same port would clash. Assumed: the command refuses with INVALID_ARGS (message naming the workspace and its home, hint: pass the --port of a registry workspace) before any mutation. Also implemented per the record: without `--port` the default 4500 selects the workspace (previously the bare-start pick).

## Suggestion

State it in the specification. Implemented meanwhile as: ASSUMPTION:dev-0403 — --port naming a workspace with a home, for a --cwd outside it, is INVALID_ARGS before any mutation.
