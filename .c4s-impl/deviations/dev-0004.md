## What I found

M02 `m02multidir` says `listMarkdownFiles(rootId)` scans the root's dir for the markdown entries `*.md`/`*.mdx` AND the raw entry `*.html` of the `pages` file map. In code (before and after the 2.1.7→2.1.8 window — the `before` text already listed `*.md`/`*.mdx`/`*.html`) `listMarkdownFiles()` on the `MarkdownFileStore` primitive (forwarded by the `PagesService` facade) returns the markdown entries only: it is the listing every reader of page content walks (M06 indexer and anchor injection, M08, M14, M19, the M17 initial `file_version` sync, the frontmatter indexer, page search), and `.html` is a raw entry with track `none` none of them may read. The raw `.html` entry is covered per root by the tree walk (`PagesService.listTree`, `fileType` from the `pages` file map) and served by M30. Returning `.html` from `listMarkdownFiles` would change page search results and capture (user-visible), and contradicts the existing test `pages.mdx.test.ts` ("excludes .html/.txt"), so the build keeps markdown-only.

## Suggestion

Reword the sentence so `listMarkdownFiles(rootId)` lists the markdown entries (`*.md`/`*.mdx`) and the root's tree (`listTree`) is what also shows the raw `*.html` entry — or name a separate full file-map listing if one is wanted.
