## What I found

M31 m31ctx001 says a «read of the workspace's project states» is not a request to a project, does not change the queue order, and puts projects whose failed-build window expired back at the end of the queue; M01 7yzu5k8u says the failed build is retried at the first request or such a read. Neither names the operation that IS that read, and the build state itself is not exposed outside ("Wystawienie go na zewnątrz należy do konsumenta"). Assumed: the read is `GET /api/workspace` — the UI's project listing that already reports per-project `live` (the switcher and /welcome) — and the `projects` list returned by `DELETE /api/workspace/projects/:id`, which is the same serialization. `list_projects` (M31 catalog) reads the registry only and is NOT such a read: it neither reorders nor re-queues. No new field is added to the response (`live` = state «ready»); exposing the five states is left to their consumer.
