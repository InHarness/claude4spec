## What I found

Three criteria embedded by the M44/M11 pages disagree with the registry rows at 2.1.57:

1. `ac-watek-context-type-brief-ma-zamontowa` says a `brief` thread mounts **only** `brief-tools`, `release-tools` and `skill-tools`. The M44 `brief` row (3f5ej79s) at 2.1.57 adds `workspace-tools`, which the turn handler appends to all four types.
2. `ac-mcp-server-c4s-tools-jest-whitelistowa` says the `c4s-tools` whitelist is enforced in `routes/chat.ts`. At 2.1.57 the turn handler assembles the set (M44 317cwhlj/3f5ej79s), and `routes/chat.ts` assembles no MCP servers.
3. `ac-wywolanie-narzedzia-spoza-whitelisty` names the wording "Tool not available in this context". That text is the agent runtime's answer to a call on an unregistered tool. The app guarantees that the server is not registered and that the error reaches the model as a `tool_result` with `isError: true`. It does not guarantee the wording.

## What was built

The code follows the rows. A brief thread mounts four servers. The criterion's test checks the three named servers, checks that entity servers, `reference-tools` and `plan-tools` are absent, and checks that `workspace-tools` is the only extra server (ASSUMPTION:dev-0014). The `c4s-tools` test checks only whether the server is present for each type. The whitelist test checks that the server is not registered and that the runtime's error is passed on.

## Suggestion

In (1), add `workspace-tools` to the criterion. In (2), name the M44 turn handler instead of `routes/chat.ts`. In (3), describe the wording as the runtime's answer, not the app's.
