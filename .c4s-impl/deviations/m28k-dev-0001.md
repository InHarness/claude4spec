## What I found

At 2.1.14 the dto `release` names its fields `created_by`, `created_at` and `count_breakdown` (snake_case), while every route that carries it (POST/GET/PATCH /api/releases…, the MCP release_create result) answers them as `createdBy`, `createdAt` and `countBreakdown` — the same camelCase the client types (`Release`, `ReleaseDetail` in src/shared/entities.ts) and every other DTO of the API use (e.g. `release-push-response`). The window changed only the dto's description and its `gitSync` field; the casing gap predates it. Assumed: the wire names stay camelCase; the `[entity:release]` tests assert every required field with its type under the camelCase name.
