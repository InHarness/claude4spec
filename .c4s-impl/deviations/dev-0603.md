## What I found

`delete-api-workspace-projects-id` and `post-api-workspace-projects` do not say what the route answers when the workspace the process serves has lost its stored registry entry since the start, for example because another process of this machine detached it. Before this fix, registration refused with a plain error (500). Removal answered 200 with the stale project list, and with `purgeData=true` it also deleted the slot.

## Suggestion

State the refusal in both endpoint records. Implemented meanwhile as ASSUMPTION:dev-0603. Both routes refuse before anything is written, retired or purged, and answer `409` with the `{ error: { code, message } }` envelope and code `WORKSPACE_NOT_REGISTERED`. That is the code the CLI already uses for a workspace this machine has not registered.
