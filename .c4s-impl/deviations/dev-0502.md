## What I found

Until 2.1.8 `.claude4spec/skills` was free for a user root (0.1.104: nothing wrote there; a test pinned `validateRootDirs` accepting a user root at `.claude4spec/skills`), and `skills` was a legal user-root id. With the `skills` system root (fixed dir `.claude4spec/skills`, reserved id `skills`) an existing project whose `roots[]` holds an entry with `id: skills`, or a root whose dir is/overlaps `.claude4spec/skills`, no longer starts (reserved-identifier error, D4 overlap error). Implemented as the specification states; no migration was added. The specification may want an edge case or a migration note for such projects (e.g. rename the root via "Change root ID" before upgrading).
