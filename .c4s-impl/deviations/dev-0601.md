## What I found

The new endpoint `GET /api/workspace` (`get-api-workspace`) answers `WorkspaceResponse` — `name`, `kind`, `lastOpenedProject`. The same path already served the UI's project listing: `mode`, `defaultPort`, `lastOpened`, and `projects[]` with id, name, cwd and live. The switcher, `/welcome`, `c4s` `confirmRemoteProject` and the e2e helpers read that listing. The M31 L4 todo says the UI registry route with the project list has no settled method or path yet.

## Suggestion

Either give the UI project listing its own endpoint, or add its fields to the record of `get-api-workspace`. Implemented meanwhile as ASSUMPTION:dev-0601: the route answers the three DTO fields plus the existing listing fields.
