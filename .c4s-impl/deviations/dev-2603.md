## What I found

At 2.1.26 the spec-operation records `link-dto` and `unlink-dto` declare `rest: via call_type_tool` with the reason 'ogólne proxy hosta dla narzędzi typów; plugin nie wnosi własnego routera'. The code says otherwise: the endpoint plugin mounts its own domain router (`plugins/c4s-plugin-api-contracts/src/entity/endpoint/index.ts:54` → `endpointsRouter` in `backend/routes.ts`: `POST /api/endpoints/:slug/dtos` and `DELETE /api/endpoints/:slug/dtos/:dtoSlug/:relation`), and the plugin frontend (`frontend/api.ts`) calls those routes, not the generic tool proxy. The catalog rows were built as the records say (via + the quoted reason), so the declaration states a reason that is false about the code. Needed from the spec: either `rest: direct` (rendered by the endpoint domain router) or a reason that matches the plugin's REST surface; or record that the domain router is to be retired in favour of the proxy.
