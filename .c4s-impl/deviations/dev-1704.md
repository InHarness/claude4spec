## What I found

M33 `ywud56l6` (2.1.17) and `ac-wyniesienie-koperty-wbudowanej-do-oso` promise that moving a built-in envelope to its own repo changes no import in its tests. The unit goal scopes the removal to the harness and the host repo's test helpers, and those are now gone from `plugins/*/test/`: ten suites import `createPluginTestApp` from `@inharness-ai/claude4spec/plugin-testing`, and the two legacy-corpus suites (which drive the host's indexer, timestamp backfill and soft-FK checker — host internals no plugin reaches) moved to `tests/integration/entities/`.

Thirty envelope test files still import host modules under `src/` that are not a running host: projection goldens (`src/server/db/projection`), `schema-diff`, `payload-upgrade`, `plugin-subagents`, `chat-context`, `registry`/`manifest`, `crud-schema-gen`, `scripts/normalize-database-table-fks.mjs`, and the real Host UI Kit components that the 2.1.19 render suites put behind their `@c4s/plugin-runtime/ui` mocks. Each of those imports would have to be rewritten on extraction, so read literally the criterion is not met by them.

## Suggestion

State whether an envelope test may import host modules that are not a running host. If it may not, name the published surface that replaces each group — e.g. the real UI kit through `vi.importActual('@c4s/plugin-runtime/ui')`, projection/serialization assertions through the harness's `db` handle or a harness helper — and the release that delivers it. Until then the guard test (`tests/integration/architecture/builtin-envelope-import-rule.test.ts`) holds the thirty files in a ratchet: no other test may leave its package, and a fixed file must be dropped from the list.
