## What I found

The pages say `config.remoteApiUrl` and the `--remote-url` start flag must be a parsable http(s) URL (`3ebblo1q`, `ux690pt2`), and say nothing about an address carrying userinfo (`https://user:secret@host`). Node's fetch refuses to send a request to such a URL ('Request cannot be constructed from a URL that includes credentials'), so a configured address with userinfo would pass the start and then fail every remote action. Assumed: an address with userinfo is refused by the same rule, with the existing error shapes — `config.json: field 'remoteApiUrl': invalid URL` for the config field, `--remote-url must be an http(s) URL, got '<value>'` for the flag (INVALID_ARGS, exit 1).

## Suggestion

State in the remote-address rule whether userinfo is allowed. Implemented meanwhile as: ASSUMPTION:dev-0802 — an address carrying userinfo is refused by isRemoteApiUrl for both config.remoteApiUrl and --remote-url, with their existing error messages.
