## What I found

M33 `m33l2001` step 1 (iii) and `ac-pakiet-z-listy-pluginow-workspace-u-k` say a listed package missing from the workspace `node_modules` 'jest pomijany z diagnozą w `plugins-status`', but no record names the diagnosis: neither the load status nor the code (the `get-api-meta-plugins` description lists only `loaded` / `skipped` with `PLUGIN_HOST_API_MISMATCH` / `PLUGIN_ENGINE_UNSATISFIED`, and `incompatible`). Assumed: status `skipped` (an environment problem, like an `engines` miss — not `failed`), new code `PLUGIN_NOT_INSTALLED`, layer `base`, a reason naming the package and the workspace `node_modules` directory and saying it must be installed there (the server never installs). It reaches `GET /api/_meta/plugins` and so `c4s plugins status` (code + reason columns). A package that IS present there but has no ESM entry stays `failed` / `PLUGIN_IMPORT_FAILED`. `c4s plugins doctor` does not aggregate the new code (it reports host-API incompatibility only).

## Suggestion

State it in the specification. Implemented meanwhile as: ASSUMPTION:dev-0301 — the diagnosis is `skipped` + PLUGIN_NOT_INSTALLED (an environment problem, like an `engines` miss), its reason naming the directory.
