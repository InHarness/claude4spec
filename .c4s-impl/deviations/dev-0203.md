## What I found

M01 row `--remote-url <url>` (flagi-cli-m01, row 9) hands the field's validation to M24 (`remoteApiUrl`: syntactically a parsable http/https URL, reachability never probed), but neither page says what the start does with an invalid or an empty `--remote-url` value, nor the message. Assumed: the flag is validated once at the start with M24's rule (`isRemoteApiUrl` in src/server/config.ts, the same check `config.remoteApiUrl` passes); an invalid value refuses the start before anything is read or written, printed as `INVALID_ARGS — --remote-url must be an http(s) URL, got '<value>'` with exit code 1 (the same INVALID_ARGS shape as an invalid `--public-url`); an empty value (`--remote-url=`) is no override, so `config.remoteApiUrl` and then the production constant still apply.

## Suggestion

State it in the specification (M01 row `--remote-url` or M24). Implemented meanwhile as: ASSUMPTION:dev-0203 — an invalid --remote-url refuses the start with INVALID_ARGS '--remote-url must be an http(s) URL, got …'; an empty value is absent.
