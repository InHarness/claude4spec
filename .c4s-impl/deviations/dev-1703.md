## What I found

`ac-cli-mcp-m11-m12-startuja-bez-serwera` (M33, section `m33edge0`) says: the CLI/MCP (M11/M12) start without a server, so the plugin loader still runs in them as a bootstrap step and their readers get the same filled registry — hence `c4s catalog`/`describe` see plugin types identically to the server.

The code has a different shape since M39 (app 0.2.13): every `c4s` discovery command is `server-delegating` (`c4s catalog` → `GET /api/projects/<id>/_meta/overview`, `c4s describe` → `/_meta/types`), and `c4s-mcp` is a stdio↔HTTP relay that never starts a server and never loads plugins. Without a server they report it as unreachable. There is no second loader at all.

The criterion's observable — catalog/describe see plugin types identically to the server — holds by construction. The implementation (2.1.17 window) pins exactly that and changes no production code: reintroducing an in-process loader would bring back the second execution locus M39 removed.

## Suggestion

Rewrite the criterion to the delegating model, e.g. "CLI and MCP have no plugin loader of their own; they read the server host's registry, so `c4s catalog`/`describe` see plugin-contributed types identically to the server", or retire it.
