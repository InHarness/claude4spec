## What I found

M17 section `ce8plh8i` names two causes of `shadow-only`: a conflicting trial merge and a git older than 2.38 (`mergeTree` → `unsupported`). M28 `eu1rffp6` also lets `mergeTree` answer `{ status: 'error' }` — any other failure of `git merge-tree` on a supported git. The specification does not say what `GET /api/shadow-diff` answers then, and the endpoint's refusals (`VALIDATION`, `GIT_UNAVAILABLE`, `SHADOW_NOT_FOUND`) do not cover it.

## Suggestion

State it in `ce8plh8i` / on `get-api-shadow-diff`. The implementation assumes (`ASSUMPTION:dev-4601`): a trial merge that fails on a supported git (and a failed file list / commit list under a detected repository) is a server fault — 500 with the shared error envelope — not a silent fall to `shadow-only`, which would present a broken merge as a conflict-free "what the shadow did".
