## What I found

The changed L11 manifest block of `code-snippet` (n6zlyrol) lists, inside the frontend module registered by the browser entry, `editorExtensions — [codeSnippetAuthoringExtension]` (slash /code-snippet + create/edit popover). That slot value is carried over unchanged from the `before_change` block — not this window's change. The package has, since earlier releases, deliberately NO module-borne `editorExtensions`: the `/code-snippet` trigger is declared once, in `contributes.commands` (`codeSnippetCommands`, carrying the `popoverKind` the host dispatches on); a second module-borne entry is the trap dev-2004 and the database-tables page (91vq520g) describe (the palette matches both, picks the module one, which carries no popover discriminator, and opens nothing). Assumed: the window's change (frontend out of the contribution, into a module the browser entry registers; renderOverlay as the content of `code-snippet-expand`) is built; the `/code-snippet` trigger stays in `contributes.commands` only. Suggestion for the spec: replace `editorExtensions — [codeSnippetAuthoringExtension]` in the n6zlyrol module comment with a note that the slash trigger is declared by `contributes.commands`, as the database-table and spreadsheet pages already do.
