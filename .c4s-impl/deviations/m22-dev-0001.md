## What I found

At 2.1.14 the c4s-spec-reader page (section `foj9tbk4`, Expanding a whole page) comments the JSON form as `c4s resolve some-page.md --format json … # writes { content, resolved: [...] }`. The command does not print that shape: `c4s resolve --format json` prints the M19 core's json result as is — `{ format, text, resolved: [...] }` (the original text plus what each tag resolved to); `content` is the field of the request body the CLI posts to the server, not of the output. The renderer otherwise emits the page 1:1. Assumed: the rendered comment keeps the real output shape (`# writes { format, text, resolved: [...] } — the original text plus what each tag resolved to`), because a skill naming a key the output lacks sends the agent looking for it.
