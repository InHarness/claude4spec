## What I found

M13 m13plenv (lifecycle, sentence 3) says the dispose of a ProjectContext does NOT call `onUnregister` — that hook belongs to axis B (pool composition) only. That holds for the BASE tier: the context's dispose never touches the process registry's plugin records (pinned by a test). For the project-local OVERLAY tier the code does call it: `loadProjectOverlay` collects each trusted overlay plugin's `onUnregister` and the context's dispose runs `overlayResult.dispose()` (src/server/core/plugin-host/overlay-loader.ts, project-context.ts dispose). The overlay is built with the context and has no reload pipeline of its own — an overlay change (M33 m33l7wch, `plugins:overlay`) IS a context rebuild, and so is a trust change — so the context's dispose is the only moment its plugins' own resources (opened in `backend.mount`, re-run by every rebuild) can be released; skipping it would leak them on every rebuild, including an activation change (axis A). Kept as is: for the overlay, the context dispose is the axis-B unregister of that tier. The spec should either state this exception for the overlay tier, or say how overlay plugins' own resources are released.
