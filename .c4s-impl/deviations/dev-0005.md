## What I found

M17 `m17reldisk` (L2-domain) shows the release metadata file `.claude4spec/releases/<slug>.json` with `roots: [{ "id": "pages", "name": "Pages", "dir": "pages" }]` and says `roots` = the list of `pages`-kind roots as `{id,name,dir}`. The code writes `roots` as a list of root ids only (`ReleaseFileData.roots: string[]`, built by `toReleaseFileData(row, slug, releasableRootIds)` in src/server/services/release-store.ts; read back by src/server/services/release-indexer.ts). This predates the 2.1.7→2.1.8 window: the window only changed WHICH roots are listed (`releasable` → kind `pages`), and the code already lists exactly the `pages`-kind roots. Switching the on-disk shape would rewrite committed release files (which the git-anchored diff treats as immutable markers) and needs a reader migration, so the build keeps the id-list shape.

## Suggestion

Either align the example and the `roots` sentence of `m17reldisk` with the id list the code writes, or schedule the `{id,name,dir}` shape as its own change with a migration of the existing release files.
