## What I found

The fork copies a plugin style into the `skills` root so that the local copy takes precedence (`oqhvnhyf`: "The local copy now takes precedence over the plugin."). But the reference plugin style `layered-vertical-slices` contributes `version: 2`, while the disk sources (`project-rooted`, `.claude/skills`) skip a package whose header `version` is above the supported 1 (`SUPPORTED_SKILL_VERSION`); the `plugin` source makes no such check. A verbatim copy would be an invalid package and the plugin would keep winning. Built: the copy's `version` is `min(plugin version, supported)`, and `forkedFrom` keeps the plugin's own version. Either the reference style's `version` should be 1 (it is a compatibility marker, not a revision), or the specification should say how the fork treats a version the disk sources do not read.
