## What I found

Within the same window two slices answer differently who refuses a leftover line window on the CLI. M11 L14 `m11dcmds` ("`c4s get-page` — format wyjścia") says `c4s get-page --range` is refused LOCALLY, before the server is called, with `INVALID_ARGS` and the hint `get-page-outline` → `get-sections`. M39 L2 `984v8437` says the CORE refuses `range` with `INVALID_ARGUMENT` and that "renderowanie operacji nie zrzuca nieznanego klucza po drodze" — and the unit m39-get-page-range read it as covering the CLI too (it switched the CLI to forward `?range=` to the core). Both forbid the silent whole page; they differ in the code and in where the refusal happens. Assumed: the CLI-owning slice (M11 L14) decides the CLI: `c4s get-page` refuses `--range` itself with INVALID_ARGS before any request; the core and the MCP renderings keep the core's INVALID_ARGUMENT.
