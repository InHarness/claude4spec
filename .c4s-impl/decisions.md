## u1-remove-release-push/p1-l1-l3 (implementer r1)

- **Route removed together with the service.** `ReleasePushService` (L2) was the only thing `routes/release-pushes.ts` served, so deleting the service without the route breaks typecheck. The route file, its mount in `project-context.ts` and `routes/release-pushes.test.ts` are deleted in this portion; the L4 portion still owns the `[entity:post-api-release-pushes|get-api-release-pushes|get-api-release-pushes-id]` absence tests (404) and `src/shared/release-push.ts` + the client side. The deleted route test also carried the current tests of six git-sync ACs (`ac-push-wydania-odrzucony-przez-remote-j`, `ac-push-bez-upstream-przy-bledzie-sie`, `ac-gitservice-push-branch-pushuje-branch`, `ac-przy-config-git-syncpushonpush-false`, `ac-przy-w-czonym-config-git-syncpushonpush`, `ac-wariant-error-gitcommitresult-gitpushres`) — all `update` in this window and rebuilt by u4-push-on-release against the new push-on-release model; they asserted the M25 push path, which no longer exists.
- **Left for u4, not dead-code-removed here:** `GitService.pushOnPush` / `branchContainingCommit` and `ReleaseService.getReleaseFilePath` lose their only production caller with the service. u4's goal removes the old M28 push entry and builds push-on-release over the same branch resolution, so removing them here would only have u4 re-add them.
- **Left for later portions:** `RemoteAuthService.getRemoteProject/updateRemoteProject`, `RemoteHttpClient.getProject/updateProject` and the `NOT_CONNECTED` / `SESSION_EXPIRED` codes still serve `/api/remote-project` (L4 portion of this unit).
- **Fixture corpus untouched.** `plugins/c4s-plugin-database-tables/test/fixtures/corpus/app-spec/release-push.json` is a frozen historical corpus whose tests pin exact counts (22 tables, dangling-FK counts); it is test data, not a counterpart of the record.

## u1-remove-release-push/p2-l4 (implementer r1)

- **Server side of M25 L4 removed here:** `routes/remote-project.ts` (+ its route test) and its mount in `project-context.ts`; `RemoteAuthService.getRemoteProject/updateRemoteProject`; `RemoteHttpClient.getProject/updateProject`, the `GetProjectResponse` / `UpdateProjectPayload` wire types, `errorEnvelopeFrom` (folded back into `errorMessageFrom`) and `RemoteRequestError.details` — all lost their only caller; the `NOT_CONNECTED` / `SESSION_EXPIRED` codes left the L3 error table for the same reason. Absence of the five deleted endpoints and five deleted DTOs is proven on a real project router in `src/server/routes/remote-push-removed.route.test.ts` (404 + no payload).
- **`remoteProjectId` left the config DTOs (app-config-response, patch-config-request):** dropped from the `GET/PATCH /api/config` response builder and from the field registry (`REMOTE_SETTINGS_FIELDS`), so PATCH ignores it silently like any non-writable key. The loader/`config.json` side (`Config.remoteProjectId`, its validation, `bootstrapDefaults`) is the code-snippet `config-json-shape` and stays for the L17 portion. The git push-toggle rename in the same DTOs is u4's and is untouched (`syncPushOnPush` still answered/accepted).
- **Left for the L5 portion (p3), because removing them here means removing the UI that is their only consumer:** `src/shared/release-push.ts`, `src/shared/remote-project.ts`, the client mirrors/calls (`src/client/lib/api.ts` `remoteProjectApi` + the `RemoteProjectInfo`/`UpdateRemoteProjectRequest` imports + `ConfigResponse.remoteProjectId` / `ConfigPatch.remoteProjectId`, `src/client/lib/release-pushes-api.ts`), the hooks `useRemoteProject` / `useReleasePushes`, the `'remote-project'` invalidation in `usePatchConfig` and in the User card logout. Those calls now hit routes that answer 404; they must go with the components in p3 so that no type or client call of a deleted DTO/endpoint survives the unit.
- **`ac-konto-z-account-status-deactivated-po`:** the deactivation tooltip shared by the sidebar slot and the User card no longer says "publishing blocked" (`DEACTIVATED_TOOLTIP = 'Account deactivated'`); the avatar dot carries `data-deactivated-badge` for the test. Session persistence is proven in `remote-account.route.test.ts`, the badge in `UserCardElement.render.test.ts`.

## u1-remove-release-push/p3-l5-l18 (implementer r1)

- **Client side of M25 removed whole:** the push action (`release/push-to-remote-action.tsx`), the "Pushed" badges (release card + `/releases` list), `UnreleasedBanner` (both places), `ReleasePushesList`, the Remote project settings card (`RemoteProjectElement` + its render test, `RELEASE_PUSH_SETTINGS`), the hooks `useReleasePushes` / `useRemoteProject`, `release-pushes-api.ts`, `remoteProjectApi` + `ConfigResponse/ConfigPatch.remoteProjectId` in `lib/api.ts`, the `release-push` modal kind (ChoiceModal now serves only `onboarding-skip`), the `remote-project-disconnect` confirm kind, the `remote-project` invalidations in `usePatchConfig` and the User card logout, and `src/shared/{release-push,remote-project}.ts`. Tests that only exercised them are deleted (`ReleaseDetail.unreleased-banner.render.test.ts`, `RemoteProjectElement.render.test.ts`, the `/releases` banner tests) or rewritten to assert the absence (`ReleasesPage.render.test.ts` `[entity:releases-list]`, `ReleaseDetail.no-push.render.test.ts` `[entity:release-detail]`).
- **M17 release-actions registry removed.** `lib/release-actions/registry.ts` had exactly one registrant — the M25 push action. With it gone `registerReleaseAction` has no caller and `listReleaseActions()` always returns `[]`; per the "unused code is always removed" rule the registry and its render loop in `ReleaseDetail` go. The view's "other modules contribute their own entries" stays true as a statement of where such an entry would go; when a module contributes one, it adds the seam back.
- **`ac-wynik-gitsync-inny-niz-status-error-c` — push half dropped** from `ReleaseDetail.gitsync.render.test.ts`: it drove the M25 "Push to remote" action, which no longer exists. The pull half stays. u4 rebuilds push-on-release (and the deferred git-sync-recover on release creation) against the new model.
- **Deactivated tooltip text** follows M24 `a21tr5i1` at 2.1.55: `This remote account is deactivated.` (p2 had `Account deactivated`); the shared constant serves both the sidebar slot and the User card badge, and the `[ac:ac-konto-z-account-status-deactivated-po]` test follows it.
- **config-json-shape:** `Config.remoteProjectId`, its default and its validation are gone from `src/server/config.ts`; a legacy key in an existing file is an unknown key (ignored on read, dropped by the next write), proven in `config.test.ts`. `release-import.ts` (M27, removed whole by u2) wrote and checked that key — `buildClonePatch` no longer writes it and the "already linked to a remote project" guard is gone, so u2's code still compiles until u2 deletes it; the `release_import.remote_project_id` column is u2's table and untouched.
- **Project card description** (`projectSettings.ts`) said the name is "used as the remote project label on first push" — no longer true; now `Name shown in the sidebar.` (not in the spec text; code-only copy).
