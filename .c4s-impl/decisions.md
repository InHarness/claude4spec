## u3-remove-bundle-archive/p1-l1 (implementer r1)

- **file-version: no migration.** The window changed only the `serializer_version` description (its M27 cross-project-import purpose went with M27); no column, type, default or index moved, so the counterpart is the existing `000_baseline.sql` table. Pre-existing differences between the record and the shipped schema (index names, missing FK, CHECKs, extra `change_summary`) are reported as `dev-0001`, not migrated.
- **Restore keyed `(rootId, path)`.** `restorePage` read `getLatestForPath(path, releaseId)` with no root, so a later version of the same path under another `pages` root (e.g. a user root) won over the base root's own past, and `restoreSpec` collected paths of every root (`listPathsForRelease` had no root filter) — a page released only under a user root was written into the base root. Both now pass the base root's id (`pagesService.rootId`, expanded to its rename chain). `listPathsForRelease` also read `release_id = ?` while its doc said at-or-before; it now reads `release_id <= ?`, so a spec restore to a release in which a page did not change still brings that page back (only caller: `restoreSpec`).
