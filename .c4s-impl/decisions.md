## u1-release-marker/p1-l2 (implementer)
- "Najpierw historia HEAD, potem wszystkie refy poza cieniami; z trafień wygrywa najstarsze dodanie" built as two sequential searches (HEAD history; then `git log --exclude='refs/runs/*' --all`), the oldest add winning within the search that answered. The release file is immutable, so a marker appears in exactly one commit and the two readings coincide; the sequential form keeps the common case to one git subprocess. The second search never runs when HEAD already answers.
- The unrestricted `--all` search is gone (no flag, no fallback); `findFirstAdd` now takes the ref arguments, and the old `--all` tests were rewritten as `[ac:ac-resolvereleasecommit-uzywa-git-log-all]` (HEAD first, other branch, shadow-only → null) and `[ac:ac-przy-switchafterrelease-off-z-commitem-n]` (named target, switch off).
- M17's consumer (`resolveReignRef`) already falls back to SQLite on a `null` marker, so the M17 changes in this window need only its doc comment; the `isAncestorOfHead` gate and the delta core stay with u2/u3.
- `commitOnRelease` omits `switched` when it did not switch (additive field); the switch-off test reads absence as `false`.

## u2-shadow-git-plumbing/p1-l4-l4 (implementer)
- Shadow filter pathspecs come from the kind declarations, not from new wiring: the effective `pages` roots of the service plus every system root whose kind has the `release` flag (`entities` today), with the `releases` root as a `:(exclude)` pathspec (a page root at `.` would otherwise enclose it).
- "Not an ancestor of HEAD" is decided by `merge-base(HEAD, tip) === tip` — the same subprocess that proves the common ancestor, so each ref costs one `merge-base` plus, when still undecided, one `diff --quiet`; refs are checked in parallel after one `for-each-ref`.
- `diffRefs` now passes its two sides as two arguments (`git diff <a> <b>`) instead of a range — identical for two commits, and it accepts a tree SHA on the right (no extra `cat-file` probe).
- The trial merge (`git merge-tree --write-tree`) is one private helper shared by `sync()` and `mergeTree()`. The git version is read once per process (`git --version`, a failure is not cached); `supportsTrialMerge(version)` is pure, so the old-git path is tested by injecting the version. `sync()` itself gets no version gate in this unit (the tech-stack part names `mergeTree`'s 'unsupported').
- `resolveShadow` and `mergeBase` have no production caller yet — they are the contract the M17 shadow diff (later unit) consumes; they are tested against a real repo here.
- Fetch and sync run the shadow fetch (`git fetch --prune <remote> +refs/runs/*:refs/runs/*`) after the upstream fetch, under the same lock; a failure of either is `error`.
- u2 review round 1: rev-0001 (unbounded per-shadow git fan-out, errors swallowed as 'no merge base') promoted to blocking per the performance rule; rev-0002 (resolveShadow accepts revision suffixes like `~1`/`@{1}`) promoted to blocking — it feeds u4's unknown-shadow refusal. The reviewer omitted `portion`; the unit has one portion, filled in by the orchestrator.
- u2 round 2 (implementer, rev-0001): `listShadows` drops the ancestors of HEAD inside the one `for-each-ref --no-merged=<HEAD>` (no per-ref subprocess for them; the `base === tip` check is gone with it), then checks the remaining refs through `mapBounded` at most `SHADOW_SCAN_CONCURRENCY` (4) at a time. `mergeBaseAt` returns `null` only for git's exit 1 (no common ancestor) and rejects otherwise; `listShadows` logs a failed merge-base / diff as a failure naming the shadow, `mergeBase`/`resolveShadow` map it to `null` with a warning — the shadow layer still never throws (contract eu1rffp6), so a failed ref is left out of the list rather than failing the GET.
- u2 round 2 (implementer, rev-0002): `resolveShadow` no longer builds a revision expression from the id. It lists `refs/runs/<id>` with `for-each-ref` (same reader as the listing) and takes the tip only of the ref whose name equals the id exactly; `~1`, `^`, `@{n}`, globs, a prefix or an empty id match no ref name → `null`. One subprocess, no extra `show-ref`/`check-ref-format` spawn.
