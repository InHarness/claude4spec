## u4-m17-create-release-channel-hook — ac-encja-zmieniona-scaleniem-sync-z-wyni (system round 1 failure)
The merged entity IS re-indexed: in production by the M31 reload `onHeadChanged` fires after `merged` (indexAll) and by the M40 chain over the labelled changed paths (m29-entity-indexer → `entity:indexed`). In the test harness the reload is not wired and the chain's only trigger was the chokidar event, whose delivery under the fork pool's load is unbounded (30 s timeout in the env) and which a live self-write guard token of the create (900 ms) would swallow on a fast host. No code defect; the test now runs the file-watch chain itself: `createPluginTestApp(..., { fsEvents: false })` + new harness `runWatchChain(source, relPath, origin)` (M40 `runChain`, resolves when every phase settled), then asserts the `entity:indexed` upsert, the merged title in the index and the unchanged entity_version count. No sleep, no polling.
