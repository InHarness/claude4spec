# u05 — non-blocking findings (round 1)

- **rev-0001** `src/server/routes/mcp.ts:203` — The set-up refusal for `brief`/`patch` in a project without `briefs` (http-mount.ts:503) reads `surface.profiles`. On the workspace-bound mount, `bindProjectPerCall` (surface.ts:566) rebuilds the surface without `profiles`, so that refusal never fires there. Here the advertised catalog comes from a template project (the compat default or the workspace's first project). If the template is a `skill` project, a `brief` handshake is accepted: `composeUncached` returns an empty project surface, so the session advertises no brief tools even for `spec` projects in the same workspace. If the template is a `spec` project, the session advertises brief tools that fail with NOT_FOUND on a call targeting a `skill` project. Nothing leaks, but the behaviour depends on which project happens to be the template. Decide, and record in decisions.md, whether the workspace mount should pass `profiles` through, refuse `brief`/`patch` only when no project in the workspace has `briefs`, or document the template-dependent result.
- **rev-0002** `src/server/services/chat-context.ts:475` — The comment says 'Both built-in names stay reserved even when a definition is not built here', but the code reserves only one name: `builtin.name` when a built-in is built, or `'diff-explore'` alone when it is not. `spec-explore` is never reserved in the diff-explore branch, and `diff-explore` is not reserved in the spec-explore branch, which is how it worked before. Either reword the comment to describe what the code does, or reserve both names (`['spec-explore','diff-explore']`) if that is the intent.
