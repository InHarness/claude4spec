# Review — m33-plugin-testing-harness

- **rev-0001** `src/server/db/index.ts:111` — The new seam is only partly applied. `openDb` now keys the slot by the caller's `baseDir` (the context build passes `registry.baseDir`), but `forgetDbSlot`, its purge-path counterpart, still builds the key from `slotDirFor` (the process-wide home). In production the two match, because `startServer` constructs `new WorkspaceRegistry()` with the default home. For any registry whose `baseDir` differs from `C4S_HOME` (exactly the case the harness creates), a purge would leave the map entry behind: the ghost-handle bug `forgetDbSlot` exists to prevent. Consider giving `forgetDbSlot` the same optional `baseDir`, or having both helpers derive the key from the registry.
- **rev-0002** `src/server/plugin-testing/index.ts:74` — `PluginTestApp` is declared twice: the implementation's interface here (express/better-sqlite3/CrudFacade types) and the published `src/plugin-types/plugin-testing.ts` (loose types). Nothing checks that the returned object conforms to the published declaration, so a field added, renamed or removed in one place can drift silently from the `.d.ts` that authors compile against (`plugin-testing.types.test.ts` compiles only against the published file). A compile-time check (for example, a type-level assignment of the implementation's `PluginTestApp` to the published one) would pin them together.
