# Review notes — u01-root-facades (non-blocking)

- **rev-0001** `src/server/services/sidebar-accordions.ts:143` — recompute() is not serialised per root. The watcher dispatches per path, so two files changing in the same reducer root at once run two recomputes concurrently. Each one awaits a directory walk and frontmatter reads, and whichever finishes last writes cache/LAST_ARRAY. A run that started earlier but finishes later overwrites the newer array with a stale one, and the WS event can be lost or duplicated. Nothing triggers this today because no kind declares a reducer, but it will once u05 adds `skills`. Coalesce per rootId (an in-flight promise plus a dirty flag, or a per-root chain) so the latest walk always wins.
- **rev-0002** `src/server/workspace/project-context.ts:1520` — rebuildAll() is fire-and-forget and ignores the context's dispose. A disposed context's late rebuild still writes the process-level LAST_ARRAY and broadcasts on its old emitter. After a rebuild it can overwrite the successor context's entry with a stale array, so the successor's next real change compares against the wrong baseline. Its event can then be suppressed, or a spurious one emitted. Stop recompute once the context is disposed, for example with a `disposed` flag checked before writing to LAST_ARRAY or the ws.
- **rev-0003** `src/server/services/sidebar-accordions.ts:214` — frontmatterFor re-implements frontmatter extraction with its own regex over a raw readFile. That duplicates the root's MarkdownFileStore, which already parses frontmatter (gray-matter) and enforces the kind's file map and path safety. Its parse can also differ from the indexer's on edge cases such as a BOM or a closing `---` at EOF without a newline. Reading through the root's store (available in storeByRootId) would keep a single parser.
- **rev-0004** `src/server/fs/sources.ts:78` — rootIdFromSource uses isSystemRootId(source) to recognise code-source names. That also accepts 'plans', 'briefs' and 'patches', which are never source names because their source is `artifacts:*`. The inverse is therefore wider than sourceNameFor. It is harmless today, but an exact inverse would be safer, for example SYSTEM_ROOTS.find(r => sourceNameFor(r) === source)?.id.
