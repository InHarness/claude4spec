# Review — m02-frontmatter-tolerant-read

- **rev-0001** `src/server/services/markdown-file-store.ts:240` — pageLabel re-implements the label chain that pages-link-indexer.ts:493 extractTitle already has (frontmatter.title -> first H1 -> fallback). The two now give different fallbacks (full relPath here, basename without .md there), so the same page can carry two different labels depending on whether it comes from GET page-detail or from the link index. The H1 regex also matches a `# comment` line inside a fenced code block that comes before the real H1. That is also true of the existing helper, but sharing one helper would keep the two in step.
- **rev-0002** `src/server/services/section-indexer.ts:160` — The literal frontmatterRaw write-back is fixed only in the two anchor write-back sites. Other server-side rewrites of a page still write { frontmatter: current.frontmatter, body } and so drop a broken header block silently: the edit_section batch (page-write.ts:1815), reference propagation on rename (references.ts:200/212/242) and section ops (sections.ts:222/231). This is outside the editor-save path the goal names, but it is the same data-loss mechanism. A small shared helper (read -> write that keeps frontmatterRaw) would close it everywhere and would replace the duplicated ternary in anchor-injection.ts and section-indexer.ts.
