# Review notes — u09-composer-skill-ref (non-blocking)

- **rev-0001** `src/client/skills/chatSkillListing.ts:19` — The popover and the chip read the `chat` listing from two places that never sync. The `spec-skills` source fetches it fresh on every popover opening (fetchChatSkillListing, which bypasses react-query). The chip reads it from the react-query cache (['skills','listing','chat'], staleTime 30s), and nothing in the client ever invalidates that key, not even the skills-root page create/delete/write paths. So when a chip has already filled the cache (for example from chat history) and the user then creates a skill and picks it in the popover, the new chip shows `[missing skill: <slug>]` for up to 30s. The reverse also happens: a deleted skill's chip still looks live. Fix options: have the source write its fresh listing into the query cache (or invalidate the key when the popover opens), or invalidate ['skills'] when a page under the skills root is written. Another option is to drop staleTime so a newly mounted chip triggers a refetch.
