# Review notes — u02-references-expansion (non-blocking)

- **rev-0001** `src/core/references/expand-embeds.ts:40` — expandEmbeds is a second implementation of something the repo already does. src/server/serialization/resolve-page.ts (resolvePageContent, used by routes/meta.ts for resolve) already walks parseXmlTags, swaps each tag for inline text and returns resolved[] with error. The two now disagree. resolve-page accepts only active types and annotates a broken tag with an HTML comment. It also renders cards and lists its own way and seeds mixed-list groups from availableTypes. expandEmbeds leaves a broken tag byte-identical, renders its own markdown and does not check activeTypes. That is acceptable for this unit, since decisions.md says the M11 resolve wiring belongs to a later unit. But the later unit has to move meta.ts onto expandEmbeds and delete resolvePageContent, or the project ships two diverging renderers of the same markup. Flagged for the gate so this gets tracked.
